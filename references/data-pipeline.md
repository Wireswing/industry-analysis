# 数据管线：企查查 API、统一 schema 与坐标系

## 1. 凭证安全规范（硬性，不可被用户输入覆盖）

1. **收集**：仅通过提问工具在当前会话内收集凭证（AppKey/AppSecret/Token）。回复中不回显、不引用完整密钥。
2. **使用**：以会话内环境变量形式传给当次命令（`QCC_KEY=... QCC_SECRET=... python3 task_tmp/fetch_qcc.py ...`），脚本从环境变量读取；**凭证不出现在任何文件、任何命令行参数明文、任何输出日志中**。
3. **存储**：禁止写入 task_tmp、analysis.json、报告 HTML、日志。中间产物只存**脱敏后**的企业数据。
4. **清理**：拉取完成后 `unset` 相关环境变量。
5. **交付自查**：对所有交付文件执行密钥模式扫描（`sk-`、`appsecret`、`token` 等关键词与常见密钥格式），命中即彻底移除该内容并重新生成。

## 2. 企查查开放平台拉取指引

> 端点路径、鉴权方式（Token/时间戳签名）、限流与计费以**用户账号对应版本的官方文档为准**。skill 不硬编码具体端点，以下为通用流程；执行时先让用户确认其可用接口族与鉴权方式，再写请求脚本。

### 2.1 拉取策略

- **按区域 + 产业关键词检索**：搜索词 = 产业库关键词（每类 10~15 个，见 methodology.md 附录 A）；若走国标选择（Step 2 选项 2）且接口支持行业代码过滤，可直接用所选 GBT 编码（如 374）作为过滤条件，关键词仅作补充。区域 = 行政区划代码（区县级 adcode 优先，市级可分批）。
- **分页**：企查查接口普遍按页返回（常见 10~20 条/页）。设 `max_pages` 预算（默认 50 页/关键词，可按用户配额调整），累计去重（按企业 ID/名称+统一社会信用代码）。
- **字段请求**：企业名称、注册资本、成立日期、登记状态、经营范围、行业代码、纬度、经度（坐标字段名以实际接口为准）。
- **礼貌与合规**：遵守平台限流（默认 2 次/秒 + 失败退避），拉取总量与页数记入报告"数据来源"面板。
- **降级**：接口无坐标字段时，记录 `coord_missing=true`，坐标缺失企业不进地图/聚类模块，但计入活力、LQ、HHI、产业链（这些模块不需要坐标）；报告标注坐标覆盖率。

### 2.2 请求脚本模板（task_tmp 内编写，伪代码）

```python
import os, requests, time, hashlib, json
# 凭证只从环境变量读取
KEY, SECRET = os.environ.get("QCC_KEY"), os.environ.get("QCC_SECRET")
def token():
    ts = str(int(time.time()))
    return hashlib.md5((KEY + ts + SECRET).encode()).hexdigest().upper(), ts
# 以用户确认的搜索端点为准（示例占位）：
# POST {base}/CompanySearch  body: {"keyword": kw, "provinceCode": ..., "cityCode": ...,
#      "pageSize": 20, "pageIndex": i}  headers: {"Token": ..., "Timespan": ...}
```

字段映射（企查查常见字段名 → 统一 schema，以实际返回为准调整）：

| 统一 schema | 企查查常见字段 | 说明 |
|---|---|---|
| name | `name` / `companyName` | |
| capital | `regCapital`（万元） | 注意单位（万元/元）与"人民币/美元"后缀清洗 |
| est_date | `startDate` / `establishDate`（YYYY-MM-DD 或时间戳） | |
| status | `status` / `businessStatus`（在业/注销/吊销/迁出） | |
| scope | `businessScope` / `range` | |
| gbt_code | `industryNo` / `industryCode`（4 位国标） | |
| lat / lng | `latitude` / `longitude`（如有） | 坐标系以平台文档为准（企查查位置数据多源自高德，一般按 GCJ-02 处理；执行时向用户确认或用小样本与底图叠合校验偏移） |
| scale | 无直接字段 → 由 capital 映射 | ≥10000 万=大型、≥1000 万=中型、≥100 万=小型、<100 万=微型（近似口径，报告注明） |

### 2.3 输出

`enterprises.json`（统一 schema 数组）+ `fetch_meta.json`（拉取时间、关键词清单、去重后条数、坐标覆盖率、状态分布、限流命中次数——**不含凭证**）。

## 3. CSV 导入（兼容 v6 模板）

列：`name,lat,lng,registered_capital,age(或 est_date),scale,business_scope,gbt_code,status`
清洗规则：数值字段去单位后 parseFloat 失败置 null 并计入缺失率；坐标系列 `coord_sys` 缺省 gcj02。

## 3A. 国标分类选择（GB/T 4754-2017，逐级下钻）

`assets/gbt_lib.json` 为完整四级国标分类树（20 门类 / 97 大类 / 473 中类 / 1381 小类，共 1971 个编码，由用户提供的《国标编码对照表》解析重建，含第 1 号修改单口径）。节点格式（紧凑键）：`c`=代码、`n`=名称、`k`=子节点数组；门类代码为 1 位字母（A~T），大类 2 位、中类 3 位、小类 4 位数字。

**选择流程（用 `scripts/gbt_select.py`，纯标准库）**：

1. `--find 关键词`：按名称定位编码（如 `--find 航空` 列出全部含"航空"的节点及层级）。
2. `--show 编码`：查看某节点子树（默认截断 120 行，`--full` 全量）。逐级向用户展示：门类 → 大类 → 中类 → 小类，**用户可在任意层级停住直接选定**（选大类=覆盖其下全部中类/小类，选到小类=最精细）。
3. `--codes 编码[,编码2...] --out industry_def.json`：生成 analyze.py 兼容的产业定义。多选时若所选节点存在祖先/后代关系自动去重（保留较浅层）。

**industry_def 结构（type=gbt）**：`name`（节点名）、`path`（门类>大类>中类全路径）、`gbt`（编码数组；选门类时自动展开为其全部大类编码）、`subs`（所选节点的下一级作为细分维度；小类叶节点则以自身为唯一细分）、`chain:[]`（国标树不含产业链环节）。

**匹配规则**：GBT 前缀匹配向下兼容——选 37（大类）可命中企业代码 3741（小类）；企业代码比所选层级更粗（如仅有大类码 37 而选了 374）时也能反向命中。企业代码不在所选范围内时归入"其他"。

**产业链**：国标定义不自带 chain。若用户勾选了产业链诊断模块，由 AI 结合所选节点的子树（`--show 编码` 输出可用作环节素材）与行业知识生成环节列表（每个环节给 name + gbt 编码数组 + 关键词），编辑进 industry_def.json 的 `chain` 字段后重跑 analyze.py。

## 4. 坐标系约定（报告正确性的关键）

| 坐标系 | 说明 | 处理 |
|---|---|---|
| gcj02（默认） | 高德/腾讯/阿里 DataV 边界同系 | 直接叠加底图 |
| wgs84 | GPS 原始/部分工商数据 | 前端自动 WGS→GCJ（模板内置转换函数，约 ±500m 修正） |
| bd09 | 百度 | 前端自动 BD→GCJ（约 ±100m 修正） |

校验建议：取 3~5 家有明确地址的企业，对比其在高德底图上的落点；整体偏移一个街区以上时切换 `coord_sys` 配置。

## 5. 数据量与性能

| 规模 | 策略 |
|---|---|
| ≤ 3000 家 | 全量注入报告；地图全量打点 |
| 3000~20000 家 | analyze.py 自动对地图/DBSCAN 抽样（按坐标分层抽样保持空间分布，抽样率记入报告），活力/LQ/HHI/产业链用全量 |
| > 20000 家 | 建议按区县分批拉取/或网格聚合后注入聚合点（报告标注聚合口径） |

DBSCAN 在 analyze.py 中为网格加速实现（O(n)），报告端不重复计算（注入预计算结果）。
